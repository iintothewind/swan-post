## 1. 整体设计哲学(四条支柱)

1. **一切皆插件,没有特权核心**(vendored Cordis 框架)
   - 模型适配器、工具注册表、session 日志、agent loop 本身都是插件。
   - 扩展 = 在旁边挂插件:`ctx.effect()` / `ctx.on()` / `ctx.waterfall()`;注册即可逆卸载。
   - 运行形态 = profile(bundle 叠加层)+ patch(cordis.patch.yml 按 row id 替换/插入),`dsh --dump-config` 可打印实际启动树,任何打印出来的 row 都可被 patch 替换。

2. **事件分三个域,选对域是每个改动的第一个决策**

   | 域 | 用途 | 例子 |
   |---|---|---|
   | session events | durable 事实,append-only 落日志,活过 reload | `turn/*`, `step/*`, `user/message`, `assistant/*`, `tool/result`, `approval/*` |
   | agent events(`agent/*`) | 观察/拦截进行中的工作 | `agent/pre-step`, `agent/request`, `agent/request-error`, `agent/turn-stopping` |
   | capability events | 给能力缝挂 policy/adapter,不 import loop | `fs/*`, `tools/*`, `llm/stream`, `telemetry/*` |

   - 瀑布(waterfall)listener 必须 `next()` 委托,否则短路整条链。
   - `agent/pre-step`、`agent/request`、`llm/stream`、`tools/*` 是瀑布;`agent/turn-stopping` 是串行事件无 `next()`。

3. **"model-visible ⟺ logged" 是全项目最硬的不变量**
   - 一切进模型请求的内容必须能从 append-only 日志重建,运行时 invariant 断言。
   - 模型历史不是维护出来的状态,而是 `deriveMessages()` 从日志派生的投影。
   - 审计、重放、fork、resume、telemetry 全部从同一条流免费获得。
   - 重建测试:`packages/core/agent-loop/tests/request-reconstruction.spec.ts`;`request/header` 事件保存完整 canonical 请求信封。

4. **Capability seam 三角色**:Service Definition(接口)/ Service Provider(实现)/ Consumer(通常是 model-facing 工具)。换 provider 即换产品行为:fs/subprocess 指向远程沙箱,Bash/PTY/LSP 一起搬家,零 provider fork。单个角色不算完整 seam。

辅助原则:fail-loud 配置(load/assembly 时抛错)、显式 > 隐式(默认值是 owning 实现里的 `resolve(request): Spec` 步骤,不是 run() 里隐藏的 `?? default`)、跨边界 id 用 branded type、信任 TypeScript 同进程类型边界只在解析器/队列/工具 JSON/持久文件/worker/进程/wire 边界做运行时校验。

## 3. 上下文管理:日志即真相

### 3.1 Session log 与派生投影
- 日志 append-only;只有三种事件类型可上 surface(user/message、assistant/message、tool/result)且**必须带 `surfaceOp` marker**(`append` 或 `{op:'replace',start,end}`);非 eligible 类型携带 marker 直接抛错(`surface.ts:184-208`)。replace 形状白名单校验:恰好 3 键,start/end 为 safe 非负整数。
- `deriveMessages()`(`core/session/src/index.ts:726-747`):增量缓存,每新 surface node 只投影一次 O(new nodes);`surface.replaceGeneration` 变化即整体重建(composition 后无 raw-log fallback);返回 fresh array,内部 Message 共享且 **deep-frozen**(内容复用已冻结的事件数据,无需二次拷贝)。
- 单节点规则 `deriveEventMessage`(`surface.ts:83-114`):user/message → verbatim 直通(**投影层禁止加 framing**,framing 由 producer 烘焙进 content);assistant/message 空 content → null(仅承载 usage 的 max-tokens 步骤不进 transcript);其余类型(chunk、turn/step 边界、log-only)→ null。
- chunk 保真:`assistant/message` 用 `sourceEventSeqs` 引用其 `assistant/chunk` 流(空数组=已知空流,缺省=legacy 未记录)。
- 崩溃修复:给未完成的 tool call 合成 `TOOL_NOT_STARTED` / `TOOL_OUTCOME_UNKNOWN` 结果,回放始终有效。
- Fork:`ctx.sessions.fork(source, boundary?, childSessionId?)`;child header 记 `parentSession`,`traceSession` 可追血缘。

### 3.2 System-prompt 组装(`core/system-prompt/src/index.ts`)
- 注册面:`section()` / `context()` / `tools()` / `variable()` → ScopedLayers(global 层 + per-agent `agent.ctx` scope 层,同名 scoped 遮蔽全局)。
- `assemble()`(467-542):变量解析(scoped 覆盖全局)→ sections 按 `order` 升序合并(-100 identity、0 persona、100–199 tool guidance 区间)→ 多个 `complete:true` section 报错 → tool providers 收集(parameters structuredClone 隔离)→ `orderTools`(`toolOrder` 配置或字典序,140-183)→ `system-prompt/assemble` waterfall(listener 结果 authoritative,complete section 之后恢复)→ suppressor 清空 contexts。
- `renderPrompt`(212-295)严格 `{{var}}` 插值:未知变量/无值/畸形组直接 throw(fail-loud)。
- 工具 schema 与 prompt section 同一 assembly 产出但分开发送;presentation mode:`native`(全量 schema)/ `code`(全部折叠进保留的 `run_code` transport + 生成的 SDK prompt section)/ `both`。

### 3.3 Request-context 注入(`packages/context/`)
- `agent-instructions`:首个 pre-step 把 `$DSH_HOME/AGENTS.md` + 项目根→cwd 的 `AGENTS.md`/`CLAUDE.md`(+`.local.md`)链折叠成一条 durable `<system-reminder>` user 消息;后续靠 first-party read/write/edit "touch" 发现嵌套文件并追加 add/update/remove 通知;SHA-1 digest 去重;`maxBytes` 由宽到窄省略;**无 watcher,touch-driven**。
- `time-context`:pre-step 注入 sourced 快照 `{kind:'plugin', plugin:'time-context', form:'snapshot'}`,正 interval 节流。
- `session-reference`:用户 `@mention` 其他会话 → `readSurface()` 有界快照(只留 direct user 文本、assistant 文本、compact checkpoint),≤3 个来源各 64KiB 上限,作为 form `'recall'` 的 sourced 消息紧跟引用之后。
- 共同点:一切注入都是带 typed `source` 的普通 `user/message` 事件 → 天然满足 model-visible ⟺ logged,重启零漂移。

## 4. Compaction:压缩即日志操作

三层拆分:Service Definition(`compaction/`)/ Provider(`compaction-basic/`)/ Consumer(`/compact` 命令)。

**触发**(`compaction-basic/src/index.ts`):
- 自动:`agent/pre-step` 压力检查,tokenMeter ≥ `thresholdRatio`(默认 0.8)× 路由模型 context window(index.ts:293-304);
- 溢出恢复:`agent/request-error` 收到 `CONTEXT_WINDOW_EXCEEDED` 绕过阈值强制削减(index.ts:179-223);
- 手动:`/compact` → `compactNow()`(index.ts:368-420,idle 才允许);`auto: false` 纯手动;`modelPolicies` 按 provider/model 覆盖策略。

**basic 策略**:
1. 可选 model-free 剪枝:`ctx.toolResultPruner` 把超限 tool/result 改写为 head 4096 + marker + tail 1026 code points(content-only replace,原事件留在日志);
2. 选区 `selectCompactableRange`(`region.ts:98-134`):尾部按 `retainRatio`(默认 0.16)或 `retainTokens` 保留近期尾巴,回退到 tool-pairing 平衡边界——**绝不切开 assistant tool-call/result 对**;
3. 摘要 = 一次性 `ctx.llm.stream()` 调用,**逐字节重放对话自己的 system prompt + tools + 被压缩区间消息**,只追加压缩指令作最后一条 user 消息以复用 provider KV cache(`summarizer.ts:121-182`,`purpose: 'compaction'`);
4. 摘要必须**严格小于**原文(region.ts:374-378),否则拒绝压缩。

**日志协议**(README 39-57):
```
compaction/start    同步 append = durable 锁(防并发压缩)
compaction/summary  log-only(摘要/shadowedSeqs/token 数/provider 信封)
user/message        唯一 surface 突变:surfaceOp:{op:'replace',start,end} + sourceEventSeqs,
                    内容 = preamble + <compacted-summary>(summarizer.ts:69,189-195)
compaction/end
```
- 崩溃留下可检测的孤儿 start,不产生虚假完成;被遮蔽(shadowed)事件永不清除,重放确定。
- 已知代价:**replace 使 KV cache 从首个被替换 token 起失效**——成本写进 README 却无法消除。

## 5. 外部记忆:没有 memory 工具,是组合拳

全仓库检索(ripgrep,200+ 匹配逐一甄别)**不存在**专门 memory tool / user-memory store。承担该角色的机制:

| 机制 | 内容 | 备注 |
|---|---|---|
| session-query | 跨会话 SQLite FTS5 检索(见下) | 最接近记忆工具 |
| session-reference | @mention 有界快照 | 用户显式触发 |
| skill catalog | durable `<available_skills>` 目录 + `skill` 工具按需加载正文 | 目录常驻、正文懒加载 |
| `~/.dsh/AGENTS.md` | 事实上的用户偏好/指令层 | agent-instructions 注入 |
| fork 血缘 | parentSession + traceSession | 结构化追溯 |

**session-query 详情**:
- API:`listSessions / readSession / filterSessions / filterEvents / listEvents`(每事件分类 current/shadowed/log-only)、`readSurface / readEvent`(before/after ≤ `readWindowMax`=50)、`traceSession / traceEvent`(祖先链 + 递归后代树;环 → `SESSION_QUERY_INVALID_LINEAGE`;replace 链追到最后一个替换)。逻辑语料 live-preferred(live 胜 persisted)。
- SQLite 后端:FTS5 `unicode61`;派生库 + 本地 TEMP 表遮蔽 durable 行;排序 = highlight span 数降序;cursor 绑定 generation;`openAt: never` 可关搜索保留精确读。
- 模型面 `tool-session-query`:5 个只读工具(`session_search` / `session_event_search` / `session_trace` / `session_event_trace` / `session_event_read`);授权 = 调用者与目标 `cwd` **字符串精确相等**(不认 symlink 等价);`session_search` 永远排除自身会话,当前会话搜索停在调用 step 之前防自匹配;**默认 composition 不挂载(opt-in)**。
- 已知弱点:FTS5 unicode61 无子串匹配(需另走 filterEvents literal scan);SQLite 用同步 `DatabaseSync` 阻塞 JS 线程;查询层本身无 caller 授权,信任边界推给工具层。

**Spill(大结果落盘)**:
- `spill-policy`:`tools/post-execute` transformer。最终 plain-text 结果 > `maxInlineBytes`(UTF-8 字节,缺省禁用)时:全文存 `ctx.spillStore`,模型只见 bounded head/tail preview + 定位符通知 `(Omitted N bytes. Full formatted result stored at: <locator>. Use read with offset/limit, or grep...)`;preview 从同一预算扣除 notice 开销,**替换体永不超上限**;best-effort,存储失败静默回退原结果绝不报错;跳过 `read` 工具(防 read→spill→read 循环)与嵌套执行。
- `spill-local`:路径 `<root>/session-<sha256(sessionId)>/<random>-<safeName>`,0600 exclusive-create 防 symlink 种植。
- **取回 = 模型自己用现有 read/grep 读该路径**;seam 刻意不做 retrieval API,检索提示由 backend 提供。locator 依赖共置 FS,远程部署需换 backend。

## 6. 工具调用循环

### 6.1 主循环状态机(`core/agent-loop/src/agent.ts`)
- 私有 `Phase` union(38-46):`idle{lastTurn} | maintenance{abort, wakeRequested} | running{turn, step, wakeRequested}`;单驱动协程 `kick` 跑 `while (await this.turn()) {}`,收敛回 idle 并重放锁存的 wake;`wakeDriver` 只从 idle 启动(172-193);disposal 不锁存 wake。
- **Turn vs Step**:step = 一次模型请求 + 其工具调用;turn = 零或多个 step。
- `turn()`(246-330):append `turn/start` → 循环 steps:
  1. `preStep`(225-243):claim inbox batch → `systemPrompt.assemble()` → **`agent/pre-step` 瀑布**(listener 可改写 claimed messages 或 `{kind:'reject'}` → turn 以 `blocked` 结束);
  2. 空首步(rejected 或改写为空)仍拥有 turn 边界但不花模型调用 → `completed`;
  3. append `step/start` → claimed messages 逐条 append 为 `user/message`(带 `surfaceOp:'append'`)→ `step()` → finally append `step/end`;
  4. **max-tokens sticky**:任一 step 触顶后,后续正常完成不得降级 turn 结果;
  5. turn 将结束但 `inbox.nextStep` 非空 → 继续(steer/inject 延长 turn);结束前发串行 `agent/turn-stopping`;
  6. catch:error 归一(`LlmError` 保真,否则 `errorChain` under `UNKNOWN`)→ `agent/error`;**finally 必 append `turn/end`**,reason ∈ `completed|max-tokens|aborted|error|blocked`;
  7. inbox 还有 pending → 重置 phase 返回 true 继续下一个 turn。
- **双通道 Inbox**(`core/agent/src/inbox.ts`):`next-turn`(每 turn 边界消费一条)/ `next-step`(每 step 边界消费整批)。入口:`followup()`=next-turn+wake;`steer()`=next-step+wake;`inject()`=next-step 不唤醒;泛化 `send(msg,target,wakeup)`。**每次变更先落 `agent/inbox/spliced` 日志再改内存**(186-192),resume 靠重放重建队列(32-39);重复 pending message id 抛错;claim 取整批 next-step + 至多一条排队的 turn。
- **取消与错误恢复**:`cancel(cause)` 清空 inbox + abort phase AbortController;wake 与 abort 竞速时重分类为 next-turn;流式中止仍持久化部分 assistant content 带 `interrupted: true`(354-370);流失败走 **`agent/request-error` 瀑布**可返回 `{kind:'retry'}`(373-389);请求组装本身可被 **`agent/request` 瀑布**扩展(基于冻结 seed config,buildRequest 426-514),并落 `request/header`(initial/resume/change)+ `request/context` diff 事件。
- 工具续转:`executeToolCalls` 的 `acceptContext` 回调把结果上下文拼进 next-step inbox;成功批次的 `concludesTurn` 结束 turn。

### 6.2 并行调度器(`core/agent-loop/src/tool-calls.ts:59-246`)
- 按 `ctx.tools.executionMode` 分组:`parallel` 进有界滚动池(`maxParallelToolCalls`),`exclusive` 形成屏障;later calls **开工前最后一刻重新分类**(registry 变更可在批次中途制造屏障)。
- 结果严格按**模型顺序** commit(`commitReady`);abort 为未派发调用合成 `ABORTED_BEFORE_DISPATCH` 保持回放有效;调度器自身失败则 drain 已启动 dispatch 但**不伪造结果**。

### 6.3 工具管线三段瀑布(`core/tools/src/index.ts`)
```
tools/pre-execute (:152)   allow | deny(reason) | ask
                           ask → approval service(未挂载则降级 deny)
                           参数改写被刻意排除(:583-591,"已落日志已展示")
                           瀑布后 per-agent guards(:711,:1110-1150)作单调第二道闸
tools/execute (:163)       around-dispatch wrapper(超时/重试/metrics)
                           wrapper 仅可换 exec.signal;registry 重融 caller 原始信号
                           (fuseToolSignals,:1532-1560)→ 取消无法脱离
tools/post-execute (:175)  accept(重写 content 或 canonical value)| additionalContexts | block
finishScheduledExecution   lossless-JSON 快照 + deep freeze → finalizeContent → tools/result 事件
```
- denial 也物化为 error result 流经 post-execute(block 反馈变成 error result)。
- `ToolDefinition`(:222-288):JSON `parameters` schema + **强制 output contract**(`output.schema` 校验 body value;pure `render` → 模型内容;`presentationMeta` → UI payload **持久化到 tool/result 事件**,回放免费);`execute(args, exec)`,exec 提供 `deferContext()` / `concludeTurn()`;可选 `timeoutMs`(**协作式,从不发给模型**);`isConcurrencySafe(args)` **fail-closed**(非精确 `true` 即 exclusive);`presentCall`/`presentResult` 纯函数(缺省 generic fallback)→ UI 流式渲染与日志回放共用。
- schema 进 prompt:构造函数注册 `ctx.systemPrompt.tools(scope => wireSchemas(scope))`(:832,:980-1001)。
- 扩展点:`register`(global 或 agent-scoped,scoped 遮蔽 global)、`restrict({allow,deny})` per-scope 过滤、`guard()`、`presentAs(mode)` per-scope presentation 覆盖、`tools/code-dispatch-log` 瀑布(Code Mode 子 dispatch 日志副本改写)。

### 6.4 Guard(`packages/guard/`)
- **repeat-tool-reminder**:纯劝告。per-agent 计数连续相同 `[toolName, canonicalized args]`(deep key-sort,属性顺序无关,:89-105),计数在 `tools/post-execute` → **denied 调用也喂给循环检测**(:181-207);阈值(默认 [3,5,8])时 prepend reminder UserMessage(source-tagged `{kind:'plugin', form:'notice'}`,永不渲染为用户发言)到 `additionalContexts`,block 结果同样生效(:213-224);从不否决或改写;真实 user message 进入 claim 即重置链(`agent/pre-step`,:229-232);配置 load 时校验(空/非整数/<2 抛错)。
- **timeout-policy**(:55-81):`tools/execute` wrapper 强制声明的 `timeoutMs`;派生 deadline signal 换上 exec、委托、finally 恢复上游信号;**仅当自己的 timer 触发**才把结果替换为 `{code:'TOOL_TIMEOUT'}`(code-scoped `timeoutOf`,嵌套外层 deadline 表现为普通取消);从不放弃或 race 工具 promise——协作式取消。

## 7. Subagent

### 7.1 三角色缝(`packages/subagent/`)
- **Service Definition** `SubagentRuntime`(`ctx.subagents`):命名 provider registry(`registerProvider` effect-scoped/HMR-safe :385-401);能力校验的一次性 `start`(:430-442,不支持的能力 ⇒ typed `SubagentError`,**绝不静默降级** :496-512);continuable 操作 `startContinuable / followup / interrupt(authority) / reportFrom(child) / drainContinuableDescendants|Children`;持久化 `listChildren/listDescendants`;lifecycle 事件 `subagent/start|end` 经 scope carrier 派发给委派父。
- **Provider 契约**(`types.ts:292-331`):`{ name, capabilities, inheritsParentContext, start(), prepareContinuable? }`;一次性 `start` 拥有 setup 直到 publication;publication 把所有权转移给 `SubagentRun { id, localAgent?, result, dispose }`,`result` resolve 不 reject(child 失败 → `stopReason`)。对 continuable child,**`prepareContinuable` 方法存在性即能力声明**,provider 只贡献 detached 数据(seed),continuation manager 拥有身份/组合/prompt/cold-resume/disposal。
- Provider 光谱:`spawn-in-process`(全新 child agent,自有 session/prompt,零父上下文)/ `fork-in-process`(以父**已完成 turn 前缀**为种子,completedTurnPrefix,`subagent-fork-in-process/src/index.ts:48-54`;continuable fork 刻意禁用,TODO :77-82 —— seeded-prefix 与 post-seed prompt sections 相互作用是个真实的坑)/ out-of-process transports:`subagent-acp` / `codex` / `claude-code` / `dsh-sdk`。

## 10. 企业 agent 借鉴清单

### 直接采用(高价值)
1. **Event-sourced 会话日志 + 派生投影**("model-visible ⟺ logged")——审计/回放/断线恢复/fork 一次解决,企业合规刚需;
2. **压缩 = 日志上的 replace 操作**:durable 锁(start 事件)+ 原始数据永存(shadowed 不删)+ 崩溃自愈可检测(孤儿 start);
3. **KV-cache 感知贯穿一切**:注入永远 append-only、summarizer 重放 warm prefix、策略 section 放保留历史之后;
4. **三段工具瀑布 + 参数不可变**:pre-execute 的 allow/deny/ask 就是权限/审批天然挂点;post-execute 改结果不碰参数;
5. **fail-closed 审批语义**:封闭结果集 + 异常/野值归一 unavailable + `never` 先于 listener 裁决(注册顺序无法破坏保证)+ asked/decided 配对审计 + open-turn 包裹;
6. **凭据引用缝**:存 env 名不存值、四层信任顺序(env > 托管店 > .env 链)、describe() 不泄值、错误不回显 secret;
7. **信号融合**:wrapper 只能换 exec.signal,registry 重融 caller 原始信号——中间件无法使取消脱离;
8. **monotone subagent 深度**持久化在 header,resume 无法重置递归预算;
9. **advisory-only 守卫**:提醒走 tagged additionalContexts(永不渲染为用户发言),从不静默否决;
10. **prepared-call 代际绑定**防热更新配置混搭;**fail-loud 配置校验**(阈值倒置、未知工具名都在 load 时抛错);
11. **UI 状态 = pure event fold(projection)**:todos/permissions/plan/approval policy 全是 last-wins 或结构化 fold,resume/fork 免费;
12. **provider 能力协商 fail-loud**:不支持即 typed error,绝不静默降级。

### 需改造后再用
- replace 型压缩的 KV cache 失效成本(首个替换 token 起)——已知、写进 README、无法消除;
- SQLite 同步 `DatabaseSync` 阻塞 JS 线程;FTS5 `unicode61` 无子串匹配;
- session-query 授权弱(cwd 字符串相等,不认 symlink 等价)——多租户需重新设计信任边界;查询层本身无 caller 授权;
- spill locator 依赖共置文件系统——远程/容器部署需换 backend;
- 审批要求 open turn(turn 外无法询问,有意的崩溃语义)、ask-user 对受托子代理直接失败——产品层要消化;
- 无用户级长期记忆——需要的话要自建(session-query 是最近替代;或参考 skill catalog 的"目录常驻+正文懒加载");
- agent-instructions 无 watcher(touch-driven)——高频变更场景需自行加监听。

### 代价意识(元启示)
- 这套 rigor 不免费:每个边界 deep-freeze/snapshot、per-execution WeakMap 记账、memoized disposal 事务、超长 invariant 注释。无多租户持久化需求的团队可用更简单的 loop。
- fork-provider 的 continuable 缺口(TODO)揭示 seeded-prefix child 与 post-seed prompt sections 的真实陷阱。
- 最值得带走的是**不变量选择方法**:把"什么必须为真"写成可断言规则(surface 类型必须带 marker、审批事件对必须配对、replace 形状白名单),机械可查的部分交给执行 gate——比抄任何单个实现都值钱。
