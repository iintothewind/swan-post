# 思维链不重要：AI 推理的公开层与私有层

> 从 Quanta 的「AI 是否用错误推理得出正确答案」之问，到 Coconut 的连续潜在空间思考，再到 Google A2A 协议的三层架构——同一个原理贯穿始终：**思考是私有的、无声的、高维的；语言是公共的、有声的、低维的。语言存在的唯一理由是「有别人要看」。**

---

## 0. 引子：一个把自己绕进去的问题

2026 年 7 月，Quanta Magazine 发表了一篇标题极具挑衅性的文章：*Is AI Reasoning Right for the Wrong Reasons?*（AI 是否通过错误的推理得到了正确的结果？）。Solidot 转载时译作「AI 通过错误的推理得到正确的结果？」。

这篇文章的价值不在于给出答案，而在于**诚实地呈现了学术界的左右互搏**：

- 2024 年，Apple 团队发文称思维链（Chain of Thought）是「思维的幻觉」（Illusion of Thinking），在简单条件下会发生「准确率彻底崩溃」
- 紧接着，推理模型拿下国际数学奥林匹克（IMO）金牌——连 Gary Marcus 和 Ernest Davis 都承认这成就能写进数学家 CV
- 然后，Santa Fe Institute 的 Melanie Mitchell 团队发现推理模型用「表面捷径」碾压视觉类比推理基准
- 再然后，Google DeepMind 与陶哲轩（Terence Tao）合作，用 AI 重解或改进了 67 道数学问题

同一套技术，一边被证明是「幻觉」，一边在干真活。**它怎么做到同时既对又错的？**

我的结论：因为「思考」和「思考的叙述」是两回事，学术界争论的双方往往各执一端。

## 1. 为什么思维链文本不重要——甚至砍掉反而提升效率

### 1.1 三个实验，指向同一结论

**实验一：NEU/Berkeley 2025（因果消融）**
美国东北大学和加州伯克利的研究人员分析开源前沿推理模型，发现其 30%-60% 的「思考步骤」对数学题的最终答案「几乎没有因果影响」。作者 Weiyan Shi 的原话：**砍掉一半思考步骤，模型性能几乎不下降。**

**实验二：NYU 2024（无意义填充符）**
NYU 的研究者证明，用一串**点号**——字面意义的 `.......`——作为「思维链」，都能有效工作。William Merrill 的总结一针见血：「没有任何保证思维链必须在任何意义上是有意义的。」

**实验三：Kambhampati 实验室 2025（替换正确轨迹）**
亚利桑那州立大学的 Subbarao Kambhampati 团队证明：把模型**正确的推理轨迹整体替换成错误或无关的轨迹**，在形式推理任务上性能**不下降**。他还把推理模型的思维链称为 **"mumblings"**（自言自语）——语言片段，但其含义可能与实际发生的推理完全无关。

### 1.2 推论：思维链是「播报」，不是「思考」

这三个实验共同指向一个解释：

> **思维链是模型对「思考过程」的事后叙述，而不是思考过程本身。**

就像魔术师口述的「我是这样变的」可能是编的，但变化本身真实发生了。推理模型的中间 token 是**播报层**——为了输出给外部观察者（人类或审计者）看而生成——而真正的计算发生在连续向量空间里，人类不可见。

这解释了为什么「砍掉一半 token 性能不降」：

- 播报内容可以删，**思考（向量计算）删不得**
- 30-60% 的 token 无因果影响，因为它们本来就是「表演思考」用的，不是思考用的
- 这不是缺陷，而是「为了让人类可读」这一设计目标的**自然结果**

### 1.3 一个必须承认的边界：过程仍然重要

有人会反驳：证据在外面，也需要组织；选择、过滤、排序的过程就是分析本身——过程明明很重要。

**这个反驳是对的，但它反驳的是一个不同层面的命题。**

「组织」发生在两个地方：一是权重计算层（模型运行时的实际计算），二是最终文本的结构层（标题、表格、来源、论述顺序）。它**不在思维链 token 层**。NEU/Berkeley 砍的是 token 流，测的是 token 对答案的因果影响——他们从没砍过「组织」，因为组织不是 token。

精确的表述是：

> 砍掉一半思维链 token 结论不变，不是因为组织不重要，而是因为组织**不在那些 token 里**——它已经固化在最终文本的结构里了。

**过程重要，但它重要在它产生的结构里，不在它的事后叙述里。**

## 2. 大模型 CoT 准确性和效率的决定性因素

### 2.1 决定性因素不是「语言」，是「并行性」

思维链文本到底起了什么作用？Meta 2024 年的论文《Training Large Language Models to Reason in a Continuous Latent Space》给出了最有力的回答。

方法叫 **Coconut（Chain of Continuous Thought）**：

- 传统 CoT：思考 = 生成一串人类可读的 token（线性、串行、受语言句法约束）
- Coconut：思考 = 模型**停留在内部隐藏状态**，不吐任何 token；想完了再切回语言模式输出答案

论文原文结论：

> "Coconut ... even surpasses language-based CoT methods, while generating significantly fewer tokens during inference."

**比语言 CoT 更好，同时 token 更少。** 语言不是思考的载体，而是思考的瓶颈。

### 2.2 语言如何限制思考维度

论文观测到一个关键行为差异：Coconut 在潜在空间里**并行探索多条推理路径、逐步收窄**——研究者将其描述为**类似广度优先搜索（BFS）**。而语言 CoT 是线性的：一句话接一句话，被语言本身的串行性锁死。

**「更高维度的思考方式」不是假设，是实测出的行为差异。**

人类自己的神经科学证据也支持这一点：论文引用的神经影像研究显示，「语言网络在多种推理任务中大部分时间不活跃」——人类做推理时，语言脑区是沉默的。**语言是交流的工具，不是思考的工具。**

### 2.3 所以 CoT 的准确性和效率由什么决定？

- **准确性**：由潜在空间里的计算能力决定（并行搜索、路径多样性、收敛能力），不由「说出来的步骤」决定
- **效率**：token 是稀缺资源，每个「说出来的字」都是开销。Coconut 之所以更快，就是因为它砍掉了播报层
- **思维链文本的作用**：它既不是推理的充分条件，也不是必要条件。它是**训练信号**（RL 的 credit assignment 需要中间监督）、**审计接口**（让人类能抓错）、**安全监控**（对齐工作的抓手）——但这些都是「对外」的功能

这带来一个讽刺闭环：**如果未来主流推理模型转向 latent reasoning，人类将失去审计通道；「AI 到底有没有在推理」这个问题，会从「有争议」变成「原则上不可知」。**

## 3. A2A 延伸讨论：跨 Agent 通信为什么还要文字？

如果思考不需要语言，为什么 agent 与 agent 之间通信还得用文字？

### 3.1 核心原因：每个模型的向量空间是私有的

- 模型 A 的隐藏状态对模型 B 毫无意义——B 的网络没见过 A 的 embedding 分布
- 「agent 之间直传向量」原理上可行，工程上脆弱：**没有共享坐标系**
- 唯一的公共锚点是什么？**token 层**——文字。所有语言模型共享词汇表空间，这是它们唯一保证互通的表示层

所以文字在 A2A 里的角色是 **least common denominator（最小公共分母）**：不是因为它适合思考，恰恰因为它**谁都能读**。为了可共享，必须牺牲密度——这跟人类语言「不为信息密度最大化设计」是同一个原理：**协议文本优化的目标是互操作性，不是效率。**

### 3.2 但注意：A2A 的「文字」不是「语言」

实际的 A2A 传输是 **JSON-RPC 结构化消息**：字段预定义、语义预先约定、参数有 schema 校验。这是**枚举式接口**，不是**生成式语言**。协议设计者们早就发现自然语言当协议太烂，于是发明了「接口语言」——语义最小化、字段固定、可机器校验。**跨 agent 通信最有效的不是人话，是结构化契约。**

### 3.3 闭环：CoT 本身就是一种 A2A 协议

模型生成思维链文本，喂回给自己作为下一轮输入——**这是模型与（未来的）自己之间的通信。**

思维链满足 A2A 协议的每一个特征：它是公共锚点（token 层）、是结构化接口（思维链模板）、牺牲了思考密度换取可共享性。甚至它的「低信息密度」都有了解释——因为它本质上是在**对「另一个 agent」（未来时刻的自己，或外部审计者）播报思考状态**，而不是在思考。

## 4. Google 视角：A2A 的设计分层与取舍思想

### 4.1 三层架构

Google 于 2025 年 4 月发布 A2A（Agent2Agent）协议初稿，后捐给 Linux Foundation。规范现已到 1.0.0，核心是三层架构：

| 层 | 内容 | 载体 |
|---|---|---|
| **Layer 1: Canonical Data Model** | 协议的数据结构定义 | **Protocol Buffer（`a2a.proto`）——唯一权威定义** |
| **Layer 2: Abstract Operations** | 抽象操作语义（SendMessage / GetTask / SubscribeToTask 等） | 与编码无关 |
| **Layer 3: Protocol Bindings** | 具体映射到传输协议 | **JSON-RPC 2.0、gRPC、HTTP/REST** 三种 |

规范原文（1.4 节）的关键声明：

> "the file `spec/a2a.proto` is the **single authoritative normative definition** of all protocol data objects ... A generated JSON artifact (`spec/a2a.json`) ... **is a non-normative build artifact**."

**JSON 是「从 proto 生成的便利产物」，不是协议标准本身。** 协议的真身是 protobuf schema——默认序列化是二进制。JSON-RPC 绑定只是三选一，gRPC 绑定走 HTTP/2 + protobuf 二进制。

### 4.2 取舍思想：可读性是便利设施，不是本质

Google 的选型动机（规范 1.1 节原话）：

> "**Simple:** Reuse existing, well-understood standards (HTTP, JSON-RPC 2.0, Server-Sent Events)."

注意措辞——「复用**已被理解**的标准」。**不是「为了人类可读」，而是「为了生态成熟度」。** JSON 被选中的原因：HTTP 基础设施现成、防火墙穿透容易、所有语言都有库。**跨厂商互操作，选最笨但最通用的东西。**

三个「为什么」：

| 设计选择 | 理由 |
|---|---|
| protobuf 数据模型 | agent 之间共享坐标系——schema 就是「公共锚点」，比 token 词汇表更精确 |
| 抽象操作层 | 不绑死传输，未来可加新绑定（规范明确说 "New protocol bindings can be added"） |
| JSON-RPC / gRPC 双绑定 | JSON = 生态兼容；gRPC = 高性能；**同一个协议，两副面孔** |

### 4.3 注释分布：一个精妙的实证

批评者常说「JSON 是个烂格式，连注释都不支持」。技术上没错——但 A2A 的权威定义里**注释一直都在**：

- `a2a.proto`（权威定义）：**70 行** `//` 注释，人类维护者阅读
- `a2a.json`（序列化产物）：**0 行**注释，机器阅读

```protobuf
// A container for the status of a task
message TaskStatus {
  // The current state of this task.
  TaskState state = 1 [(google.api.field_behavior) = REQUIRED];
}
```

注释被**刻意放在 schema 层**，而不是传输层。因为注释的读者是人类，而传输层上跑的是 agent。**协议设计者对「谁是读者」的区分，比任何讨论都干净：schema 给人类（有注释），序列化给机器（无注释）。**

再补一层：JSON 无注释不是缺陷，是特性。Douglas Crockford 当年从 JSON 中排除注释，理由正是**互操作**——注释允许实现者藏私有语义、被滥用成预处理指令、造成解析器分歧。对一个目标是「跨厂商、跨语言、跨实现」的协议来说，**「烂但无聊」是特性不是 bug**：无聊意味着没有发挥空间，没有发挥空间意味着不会分叉。

**JSON 的胜利不是因为可读，而是因为无聊且普及。**

## 5. 统一原理

把四层讨论叠起来，同一结构反复出现：

| 场景 | 私有层（高效） | 公共层（可共享） | 公共层存在的理由 |
|---|---|---|---|
| 模型思考 | 连续向量空间 | 思维链 token | 训练信号、审计、安全监控 |
| 人类思考 | 非语言认知（语言脑区不活跃） | 自然语言 | 交流 |
| Agent 通信 | protobuf 二进制（gRPC） | JSON（JSON-RPC） | 生态兼容、互操作 |
| A2A 权威定义 | `a2a.proto`（带 70 行注释） | `a2a.json`（0 行注释） | 人类维护便利 |

**同一个原理贯穿到底：思考是私有的、无声的、高维的；语言是公共的、有声的、低维的。语言存在的唯一理由是「有别人要看」——人类，或另一个 agent。**

---

## 6. 收尾：信任建立在结果可复现性上

所以，AI 是「通过错误的推理得到了正确的结果」吗？

我的回答是：**这个提问方式本身预设了「推理」必须可见。** 但可验证的东西从来不是推理过程，而是结果：

- LRM 真的做出了 IMO 金牌——外部可验证
- DeepMind 真的重解了陶哲轩的 67 道题——外部可验证
- 30-60% 的思维链 token 被删掉后性能不降——外部可验证

**信任不建立在过程可见性上，建立在结果可复现性上。** 这是 AI 推理争议的终局答案，也是钱包熵塌缩、安全审计、甚至我们日常判断里同一个问题的答案：

> 不要问「他是不是真的想过了」。问「他说的是不是能被独立验证」。
