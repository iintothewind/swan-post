## 1. Overall Design Philosophy (four pillars)

1. **Everything is a plugin; there is no privileged core** (vendored Cordis framework)
   - The model adapter, the tool registry, the session log, and the agent loop itself are all plugins.
   - Extension = mounting a plugin beside the others: `ctx.effect()` / `ctx.on()` / `ctx.waterfall()`; registration is reversible on unload.
   - Runtime shape = profile (stacked bundle layers) + patch (cordis.patch.yml replaces/inserts rows by id); `dsh --dump-config` prints the actually-booted tree, and any printed row can be overridden by a patch.

2. **Events fall into three domains; picking the right domain is the first decision of most changes**

   | Domain | Purpose | Examples |
   |---|---|---|
   | session events | durable facts, append-only to the log, survive reload | `turn/*`, `step/*`, `user/message`, `assistant/*`, `tool/result`, `approval/*` |
   | agent events (`agent/*`) | observe / intercept in-flight work | `agent/pre-step`, `agent/request`, `agent/request-error`, `agent/turn-stopping` |
   | capability events | attach policy/adapters to a seam without importing the loop | `fs/*`, `tools/*`, `llm/stream`, `telemetry/*` |

   - Waterfall listeners must `next()` to delegate, otherwise they short-circuit the chain.
   - `agent/pre-step`, `agent/request`, `llm/stream`, `tools/*` are waterfalls; `agent/turn-stopping` is a serial event with no `next()`.

3. **"model-visible ⟺ logged" is the single hardest invariant**
   - Everything that reaches a model request must be reconstructable from the append-only log; a runtime invariant asserts it.
   - Model history is not maintained state; it is a projection derived by `deriveMessages()`.
   - Audit, replay, fork, resume, and telemetry all come free from the same stream.
   - Reconstruction test: `packages/core/agent-loop/tests/request-reconstruction.spec.ts`; the `request/header` event stores the full canonical request envelope.

4. **Capability seam = three roles**: Service Definition (interface) / Service Provider (implementation) / Consumer (typically a model-facing tool). Swapping a provider swaps the whole product's behavior — point fs/subprocess at a remote sandbox and Bash/PTY/LSP move together with zero provider forks. A single role is not a complete seam.

Supporting principles: fail-loud config (throw at load/assembly), explicit > implicit (a default is an explicit `resolve(request): Spec` in the owning implementation, never a hidden `?? default` inside `run()`), cross-boundary ids use branded types, trust TypeScript at same-process type boundaries and only validate at parser/queue/tool-JSON/durable-file/worker/process/wire boundaries.

## 3. Context Management: the log is the truth

### 3.1 Session log and derived projection
- Log is append-only; only three event types may reach the surface (user/message, assistant/message, tool/result) and they **must carry a `surfaceOp` marker** (`append` or `{op:'replace',start,end}`); a non-eligible type carrying a marker throws directly (`surface.ts:184-208`). The replace shape is whitelist-validated: exactly 3 keys, start/end are safe non-negative integers.
- `deriveMessages()` (`core/session/src/index.ts:726-747`): incremental cache, each new surface node projected only once O(new nodes); `surface.replaceGeneration` change forces a full rebuild (no raw-log fallback after composition); returns a fresh array while internal Message objects are shared and **deep-frozen** (content reuses already-frozen event data, no second clone needed).
- Per-node rule `deriveEventMessage` (`surface.ts:83-114`): user/message → verbatim pass-through (**no framing may be added at the projection layer** — framing is baked into content by the producer); assistant/message with empty content → null (a max-tokens step hosting only usage does not enter the transcript); other types (chunks, turn/step boundaries, log-only) → null.
- Chunk fidelity: `assistant/message` references its `assistant/chunk` stream via `sourceEventSeqs` (empty array = known empty stream, absent = legacy unrecorded).
- Crash repair: synthesize `TOOL_NOT_STARTED` / `TOOL_OUTCOME_UNKNOWN` results for incomplete tool calls so replay always stays valid.
- Fork: `ctx.sessions.fork(source, boundary?, childSessionId?)`; child header records `parentSession`, `traceSession` follows lineage.

### 3.2 System-prompt assembly (`core/system-prompt/src/index.ts`)
- Registration surface: `section()` / `context()` / `tools()` / `variable()` → ScopedLayers (global layer + per-agent `agent.ctx` scope layer, same-name scoped shadows global).
- `assemble()` (467-542): resolve variables (scoped overrides global) → merge sections by ascending `order` (-100 identity, 0 persona, 100–199 tool-guidance band) → multiple `complete:true` sections is an error → collect tool providers (parameters isolated via structuredClone) → `orderTools` (`toolOrder` config or lexicographic, 140-183) → `system-prompt/assemble` waterfall (listener result authoritative, complete sections still restore after) → suppressor clears contexts.
- `renderPrompt` (212-295) does strict `{{var}}` interpolation: unknown variable / no value / malformed group throws (fail-loud).
- Tool schema and prompt sections are produced by the same assembly but sent separately; presentation mode: `native` (all schemas) / `code` (everything collapsed into a reserved `run_code` transport + generated SDK prompt section) / `both`.

### 3.3 Request-context injection (`packages/context/`)
- `agent-instructions`: on the first pre-step, folds `$DSH_HOME/AGENTS.md` + project-root→cwd `AGENTS.md`/`CLAUDE.md` (+`.local.md`) chain into one durable `<system-reminder>` user message; subsequently discovers nested files via first-party read/write/edit "touch" and appends add/update/remove notices; SHA-1 digest dedup; `maxBytes` narrows wide-to-narrow; **no watcher, touch-driven**.
- `time-context`: injects a sourced snapshot at pre-step `{kind:'plugin', plugin:'time-context', form:'snapshot'}`, throttled on a positive interval.
- `session-reference`: user `@mention` of another session → `readSurface()` bounded snapshot (keeps only direct user text, assistant text, compact checkpoint), ≤3 sources each ≤64KiB, as a sourced message with form `'recall'` placed right after the referencing message.
- Common property: every injection is an ordinary `user/message` event with a typed `source` → automatically satisfies model-visible ⟺ logged, zero drift across restart.

## 4. Compaction: compression is a log operation

Three-layer split: Service Definition (`compaction/`) / Provider (`compaction-basic/`) / Consumer (`/compact` command).

**Trigger** (`compaction-basic/src/index.ts`):
- Automatic: `agent/pre-step` pressure check, tokenMeter ≥ `thresholdRatio` (default 0.8) × routed model context window (index.ts:293-304);
- Overflow recovery: `agent/request-error` receiving `CONTEXT_WINDOW_EXCEEDED` forces a reduction bypassing the threshold (index.ts:179-223);
- Manual: `/compact` → `compactNow()` (index.ts:368-420, only when idle); `auto: false` for manual-only; `modelPolicies` overrides per provider/model.

**basic strategy**:
1. Optional model-free pruning: `ctx.toolResultPruner` rewrites oversized tool/result to head 4096 + marker + tail 1024 code points (content-only replace, original event stays in the log);
2. Range selection `selectCompactableRange` (`region.ts:98-134`): keep a recent tail by `retainRatio` (default 0.16) or `retainTokens`, falling back to a tool-pairing balanced boundary — **never split an assistant tool-call/result pair**;
3. Summary = a single `ctx.llm.stream()` call that **replays verbatim the conversation's own system prompt + tools + the compacted range's messages**, appending only the compaction instruction as the last user message to reuse the provider KV cache (`summarizer.ts:121-182`, `purpose: 'compaction'`);
4. The summary must be **strictly smaller** than the original (region.ts:374-378), otherwise compaction is rejected.

**Log protocol** (README 39-57):
```
compaction/start    synchronous append = durable lock (prevents concurrent compaction)
compaction/summary  log-only (summary / shadowedSeqs / token count / provider envelope)
user/message        the only surface mutation: surfaceOp:{op:'replace',start,end} + sourceEventSeqs,
                    content = preamble + <compacted-summary> (summarizer.ts:69,189-195)
compaction/end
```
- A crash leaves a detectable orphan `start` rather than a false completion; shadowed events are never deleted, replay is deterministic.
- Known cost: **replace invalidates the KV cache from the first replaced token** — documented in the README but irreducible.

## 5. External memory: no memory tool, it is a combination

A repo-wide search (ripgrep, 200+ matches individually screened) found **no dedicated memory tool / user-memory store**. The mechanisms playing that role:

| Mechanism | Content | Notes |
|---|---|---|
| session-query | cross-session SQLite FTS5 search (see below) | closest to a memory tool |
| session-reference | @mention bounded snapshot | user-triggered |
| skill catalog | durable `<available_skills>` list + `skill` tool loads body on demand | list resident, body lazy |
| `~/.dsh/AGENTS.md` | de-facto user-preference / instruction layer | injected by agent-instructions |
| fork lineage | parentSession + traceSession | structured traceability |

**session-query details**:
- API: `listSessions / readSession / filterSessions / filterEvents / listEvents` (each event classified current/shadowed/log-only), `readSurface / readEvent` (before/after ≤ `readWindowMax`=50), `traceSession / traceEvent` (ancestor chain + recursive descendant tree; cycle → `SESSION_QUERY_INVALID_LINEAGE`; replace chain follows to its last replacement). Logical corpus is live-preferred (live beats persisted).
- SQLite backend: FTS5 `unicode61`; derived DB + local TEMP tables shadow durable rows; sort = descending highlighted span count; cursor bound to generation; `openAt: never` keeps precise reads with search disabled.
- Model-facing `tool-session-query`: 5 read-only tools (`session_search` / `session_event_search` / `session_trace` / `session_event_trace` / `session_event_read`); authorization = caller's `cwd` **exactly equal** to the target's (no symlink-equivalence recognition); `session_search` always excludes the self session, and a search of the current session stops before the calling step to avoid self-match; **not mounted by default composition (opt-in)**.
- Known weaknesses: FTS5 unicode61 has no substring matching (needs a separate filterEvents literal scan); SQLite uses synchronous `DatabaseSync` blocking the JS thread; the query layer itself has no caller authorization, trusting the tool layer for the trust boundary.

**Spill (oversized result offload)**:
- `spill-policy`: `tools/post-execute` transformer. When the final plain-text result exceeds `maxInlineBytes` (UTF-8 bytes, disabled by default), the full text is stored in `ctx.spillStore` and the model sees only a bounded head/tail preview + a locator notice `(Omitted N bytes. Full formatted result stored at: <locator>. Use read with offset/limit, or grep...)`. The preview deducts the notice overhead from the same budget, the **replacement never exceeds the cap**; best-effort — if storage fails it silently falls back to the original result and never errors; skips the `read` tool (prevents read→spill→read loop) and nested execution.
- `spill-local`: path `<root>/session-<sha256(sessionId)>/<random>-<safeName>`, 0600 exclusive-create to prevent symlink planting.
- **Retrieval = the model itself uses the existing `read`/`grep` tools on that path**; the seam deliberately provides no retrieval API, and the retrieval hint is supplied by the backend. The locator depends on a co-located filesystem; remote deployment needs a different backend.

## 6. Tool-calling loop

### 6.1 Main loop state machine (`core/agent-loop/src/agent.ts`)
- Private `Phase` union (38-46): `idle{lastTurn} | maintenance{abort, wakeRequested} | running{turn, step, wakeRequested}`; a single driver coroutine `kick` runs `while (await this.turn()) {}`, returns to idle and replays a latched wake; `wakeDriver` only starts from idle (172-193); disposal never latches a wake.
- **Turn vs Step**: a step = one model request plus the tools it calls; a turn = zero or more steps.
- `turn()` (246-330): append `turn/start` → loop steps:
  1. `preStep` (225-243): claim inbox batch → `systemPrompt.assemble()` → **`agent/pre-step` waterfall** (listeners may rewrite claimed messages or return `{kind:'reject'}` → turn ends `blocked`);
  2. an empty first step (rejected or rewritten empty) still owns the turn boundary but spends no model call → `completed`;
  3. append `step/start` → claimed messages appended one-by-one as `user/message` (with `surfaceOp:'append'`) → `step()` → finally append `step/end`;
  4. **max-tokens sticky**: once any step hits the ceiling, later normally-completed steps must not downgrade the turn outcome;
  5. turn about to end but `inbox.nextStep` non-empty → continue (steer/inject extends the turn); fire serial `agent/turn-stopping` before ending;
  6. catch: error normalized (`LlmError` keeps facts, otherwise `errorChain` under `UNKNOWN`) → `agent/error`; **finally always appends `turn/end`**, reason ∈ `completed|max-tokens|aborted|error|blocked`;
  7. inbox still has pending → reset phase and return true for the next turn.
- **Dual-channel Inbox** (`core/agent/src/inbox.ts`): `next-turn` (one message consumed per turn boundary) / `next-step` (whole batch consumed per step boundary). Entry points: `followup()` = next-turn + wake; `steer()` = next-step + wake; `inject()` = next-step without waking; generic `send(msg,target,wakeup)`. **Every mutation first appends an `agent/inbox/spliced` log event before mutating the in-memory projection** (186-192), so resume rebuilds the queue by replay (32-39); duplicate pending message ids throw; claim takes the full next-step batch plus at most one queued turn message.
- **Cancellation and error recovery**: `cancel(cause)` clears the inbox + aborts the phase AbortController; a wake racing an abort is reclassified to next-turn; mid-stream abort still persists partial assistant content with `interrupted: true` (354-370); stream failure goes through the **`agent/request-error` waterfall** which may return `{kind:'retry'}` (373-389); request composition itself is extensible via the **`agent/request` waterfall** over the frozen seed config (buildRequest 426-514), and logs `request/header` (initial/resume/change) + `request/context` diff events.
- Tools continuing the turn: `executeToolCalls`' `acceptContext` callback splices result contexts into the next-step inbox; a successful batch's `concludesTurn` ends the turn.

### 6.2 Parallel scheduler (`core/agent-loop/src/tool-calls.ts:59-246`)
- Grouped by `ctx.tools.executionMode`: `parallel` calls fill a bounded rolling pool (`maxParallelToolCalls`), `exclusive` calls form barriers; later calls are **reclassified just before dispatch** (a registry change can create a barrier mid-batch).
- Results commit strictly in **model order** (`commitReady`); abort synthesizes `ABORTED_BEFORE_DISPATCH` for undelivered calls to keep replay valid; a scheduler-internal failure drains already-started dispatches but **never fabricates results**.

### 6.3 Tool pipeline, three-stage waterfall (`core/tools/src/index.ts`)
```
tools/pre-execute (:152)   allow | deny(reason) | ask
                           ask → approval service (demotes to deny if not mounted)
                           argument rewriting deliberately excluded (:583-591, "already logged and presented")
                           after the waterfall, per-agent guards (:711, :1110-1150) act as a monotonic second gate
tools/execute (:163)       around-dispatch wrapper (timeout/retry/metrics)
                           wrapper may only replace exec.signal; registry re-fuses the caller's original signal
                           (fuseToolSignals, defined :1889; invoked from dispatchToolBody :1537) → cancellation cannot be detached
tools/post-execute (:175)  accept (rewrite content or canonical value) | additionalContexts | block
finishScheduledExecution   lossless-JSON snapshot + deep freeze → finalizeContent → tools/result event
```
- A denial is also materialized as an error result that flows through post-execute (a block's feedback becomes an error result).
- `ToolDefinition` (:222-288): JSON `parameters` schema + **mandatory output contract** (`output.schema` validated against the body value; pure `render` → model content; `presentationMeta` → UI payload **persisted on the `tool/result` event** for free replay); `execute(args, exec)` where exec provides `deferContext()` / `concludeTurn()`; optional `timeoutMs` (**cooperative only, never sent to the model**); `isConcurrencySafe(args)` **fail-closed** (anything but exact `true` is exclusive); `presentCall`/`presentResult` pure functions (generic fallback if omitted) → shared by UI streaming and log replay.
- Schema enters the prompt via the constructor registering `ctx.systemPrompt.tools(scope => wireSchemas(scope))` (:832, :980-1001).
- Extension points: `register` (global or agent-scoped, scoped shadows global), `restrict({allow,deny})` per-scope filter, `guard()`, `presentAs(mode)` per-scope presentation override, `tools/code-dispatch-log` waterfall (rewrite Code Mode sub-dispatch log copies).

### 6.4 Guard (`packages/guard/`)
- **repeat-tool-reminder**: purely advisory. Counts consecutive identical `[toolName, canonicalized args]` per agent (deep key-sort so property order is irrelevant, :89-105), counting inside `tools/post-execute` so **denied calls also feed the loop detector** (:181-207); at thresholds (default [3,5,8]) it prepends a reminder UserMessage (source-tagged `{kind:'plugin', form:'notice'}`, never renders as a user turn) onto the decision's `additionalContexts`, including on `block` outcomes (:213-224); never vetoes or rewrites; any claimed step containing a real user message resets the chain (`agent/pre-step` listener, :229-232); config fails loud at load (empty / non-integer / <2 throws).
- **timeout-policy** (:55-81): `tools/execute` wrapper enforcing the declared `timeoutMs`; derives a deadline signal, swaps it onto `exec`, delegates, restores the upstream signal in `finally`, and replaces the result with `{code:'TOOL_TIMEOUT'}` **only when its own timer fired** (code-scoped via `timeoutOf`, so a nested outer deadline reads as an ordinary cancel); never abandons or races the tool promise — cooperative cancellation only.

## 7. Subagent

### 7.1 Three-role seam (`packages/subagent/`)
- **Service Definition** `SubagentRuntime` (`ctx.subagents`): named provider registry (`registerProvider` effect-scoped / HMR-safe :385-401); capability-validating one-shot `start` (:430-442, unsupported capability ⇒ typed `SubagentError`, **never silent degradation** :496-512); continuable ops `startContinuable / followup / interrupt(authority) / reportFrom(child) / drainContinuableDescendants|Children`; persistence-backed `listChildren`/`listDescendants`; lifecycle events `subagent/start|end` dispatched through a scope carrier keyed by the delegating parent.
- **Provider contract** (`types.ts:292-331`): `{ name, capabilities, inheritsParentContext, start(), prepareContinuable? }`; one-shot `start` owns setup until publication; publication transfers ownership to `SubagentRun { id, localAgent?, result, dispose }` whose `result` resolves (never rejects on child failure) with `{ output, structured?, diagnostic?, stopReason }`. For a continuable child, **the presence of `prepareContinuable` is the capability declaration** — the provider contributes only detached data (an optional seed); the continuation manager owns identity, composition, prompts, cold-resume, and disposal.
- Provider spectrum: `spawn-in-process` (brand-new child agent, own session/prompt, zero parent context) / `fork-in-process` (seeded with the parent's **completed-turn prefix**, `completedTurnPrefix`, `packages/subagent/subagent-fork-in-process/src/index.ts:48-54`; continuable fork deliberately disabled, TODO :77-82 — seeded-prefix interacting with post-seed prompt sections is a real trap) / out-of-process transports: `subagent-acp` / `codex` / `claude-code` / `dsh-sdk`.
- **Consumers**: `tool-subagent` (delegation entry; config picks provider; background `one-shot|continuable`; default `maxDepth: 3`; persona/toolFilter passthrough), `tool-subagent-control` (messaging/listing), `tool-subagent-report` (child→parent channel).

### 7.2 Continuable machinery (`subagent/src/continuation.ts`)
- `Activation` (:197-246) = one residency epoch of a durable child: retained AgentHandle, WeakSet ancestry, owned children blocking settlement, memoized `disposal` promise doubling as admission cutoff; per-child ops serialize through `ChildLock` (:326-347).
- `materialize`: create fresh (provider spec + delegated policy capture) or **cold-resume** from a persisted session; settlement delivers a plain-language notice into the **parent's inbox** ("Background subagent <id> finished…", :297-318) rather than resolving a promise.
- `interrupt` requires a human-parent address or exact live-ancestor authority; lineage checks (:1273) prevent cross-tree tampering.

### 7.3 Transcript and depth
- Each child is an independent Session whose header records `parentSession`; the resolved `subagent/descriptor` event is appended inside the **child's own initial turn** (pre-step hook, `in-process-driver/src/index.ts:79-89`), keeping the parent log clean; discovery folds child logs.
- Depth (`depth.ts:28-36`): `max(header.delegationDepth, runtime option)` — monotone, so a resumed child **cannot reset its recursion budget**.

### 7.4 experimental/agent-team (experimental)
- `TeamService` (:56-115) = façade over TeamRoster (members, default cap 8) / TeamMailbox (64 msgs × 64KiB) / TeamTaskBoard (256 tasks) / TeamJournal + TeamActivity/Lifecycle — **all state folded from the Lead's own session log** (crash-safe recovery on `agent/session-start`).
- Members spawned as continuable subagents; `tryMembership` (roster.ts:91-121) classifies any live agent whose parentSession points at a rostered root as teammate, otherwise a fresh implicit lead ('lead' pseudo-member); mailbox delivery rides the normal inbox; limits enforced deployment-side.

### 7.5 Scope (`core/scope`)
- `createScope(ctx, key)` (:137-147): mints a Cordis fiber carrying an opaque scope tag for every agent (agent-loop constructor agent.ts:94-95).
- Event routing `scopeTarget(base, key)` (:170-185): untagged listeners see everything; a tagged listener receives a dispatch only if its key sits on the target's **ancestor chain** (events flow up, never down) — a single standing composition observes all its agents while an agent-scoped plugin sees only its own calls (e.g. `tools/pre-execute` dispatched on `exec.agent`).
- Parent links are bind-once with cycle detection and a privileged `rebind` (:42-82).

## 8. User interaction

### 8.1 Approval seam (`interaction/user-approval/src/index.ts`)
- `ApprovalService` (`ctx.approval`, L192), sole entry `request(req)` (L257): **asserts an open turn** (L259; reason: the audit event pair must lie within the durable log's commit/replay boundary, L121-126) → append `approval/asked` → `decide()` → append `approval/decided` (same id paired; pure audit, not in the model transcript, L44-58).
- `decide()` (L304) order: signal already aborted → `cancelled`; policy=`never` rejects **before dispatch** (L312, specifically to prevent a `prepend:true` listener from bypassing determinism); otherwise a scope-filtered waterfall `'approval/request'` (L317); default / thrown / illegal return all normalize to `unavailable` (**fail-closed**, L320-328); a signal abort racing the answer drops a late answer by construction (L330-343).
- Result vocabulary closed: `allowed-once | rejected | cancelled | unavailable` (types.ts L28); the only grant type, and exactly once.
- Policy is log state: `approval/policy` last-wins fold (L112); `setPolicy` (L226) toggles and injects a user message notifying the model; the current policy is placed after the retained history via a system-prompt section (order 115) so it does not break the KV-cache prefix (L204-216).
- Tool trigger point: `core/tools` L1689-1712, when a pre-tool decision is `ask` it opportunistically takes `ctx.get('approval')` (demotes to deny if unmounted), with payload `{agent, toolName, callId, reason, signal}`; answering frontends mount waterfall listeners (web: `host/apiproxy/src/api-proxy.ts:1363`; ACP: `acp/acp/src/index.ts:271`).

### 8.2 Ask-user (`interaction/user-questions`)
- `ctx.userQuestions` holds a single UI provider (`registerProvider` L64, duplicate registration throws); `ask()` (L92) validates: aborted / empty question / exact-live-root (`CALLER_NOT_LIVE`; `DELEGATED_CALLER` — an owned subagent would block forever, so rejected directly, L99-113) / intent validity (L121-135).
- Model-facing `tool-ask-user` registers `ask_user_question`: its execute asks and **feeds the answer back to the loop as an ordinary tool result** — the tool call is the pause point.

### 8.3 Commands / Permission presets / Plan mode
- `commands`: `CommandRuntime` (`ctx.commands`) registers slash commands; `parseCommand` (L116) + `execute` (L329) intercept `/xxx` at the UI layer, **model never invoked**; before/after the handler it appends log-only `command/run`/`command/done` (thrown also settles as error, L340-356); image admission enforced at the registry (L358); scoped layer supports per-agent shadowing of globals (L435).
- `permission-presets`: a preset = sandbox × approval bundle (default `workspace-write`+ask, `danger-full-access`+never, L183); the `/permission` write path records a `permission/preset` user intent first, then lands via each knob's canonical setter (L391-408); read path = `permissions` projection (fold L129) for the UI; construction requires a confining executor or throws (L208).
- `plan-mode` (`plan/plan-mode/src/index.ts`): `plan/mode {active}` last-wins fold (L129) → zero catch-up on resume/fork; `/plan` (L295) → pending (WeakMap) inside an open turn, appended with narrative by an `agent/pre-step` listener once the step is admitted (L223-240), or committed immediately outside a turn; exit review: `exit_plan_mode` tool (L342) validates # heading then sends a plan-review question via `userQuestions.ask` (`intent:{kind:'plan-review', approve:'Approve'}`, L384); Approve → pending takes effect silently; "Keep planning" / custom feedback returns to the model as an Error (L407-411); `plan` projection {active,pending} is a pure replay derivation (L261). **Design choice: plan state is prompt guidance only, not a hard constraint; hard limits rest on the sandbox/approval knobs independently; the exit tool stays registered to keep the tool catalog stable.**

### 8.4 Todo (`todo/tool-todo`)
- `todo_write` replaces the whole table, appending a `todo/write` snapshot each time (L213), last-write-wins; UI reads the `todos` projection (cleared on turn/start, retained on turn/end, L135-148); model receives a counts-structured result (L215); `allowParallelInProgress` is a deployment-required policy that changes both the tool description and validation (L37, L107).

## 9. Model connection

### 9.1 Adapter seam (`llm/llm/src/index.ts`)
- `LlmRuntime` (`ctx.llm`, L311) = adapter registry (`registerAdapter` L365 all-or-nothing + atomic `replace` L385) + configurable-provider catalog (L458) + discovery (L531); `stream()` (L985) passes through the `'llm/stream'` waterfall (L993), interceptable/short-circuitable by middleware.
- abstract `LlmAdapter` (L191) must implement only `stream`; `prepareCall` (L824) binds model metadata and dispatch to one registration generation, the prepared call is single-use, config frozen-compared (`INVALID_PREPARED_CALL`) — prevents generation mix-ups from settings/HMR; `forAdapter` (L878) strips another provider's replayState.

### 9.2 Stream vocabulary and errors (`llm/llm/src/types.ts`)
- `StreamChunk` (L312): block-start / text-delta / reasoning-delta / tool-call-delta / block-end / usage / finish; `FinishReasonMap` (L116): stop / tool-calls / max-tokens / **aborted / error (with LlmFailure)**; ContentBlock/FinishReason are merge-extensible; ReplayEnvelope (L290) carries adapter-private replay metadata.
- Errors: adapter throws are normalized in `adapterStream` to a terminal finish chunk (L1003; middleware/consumer errors still thrown); `LlmError extends HarnessError` is serializable (status/retryAfterMs/requestId); `assertUsableApiKey` (L138) diagnoses credentials but **never echoes the key**.

### 9.3 Retry (`retry-policy.ts` + llm-retry plugin)
- Owned entirely by the provider router: normal default 5 attempts, backoff 500ms→10s ±10% jitter, retryable = RATE_LIMIT/SERVER/TIMEOUT/TRANSPORT/EMPTY_RESPONSE (or always); executed by the optional `llm-retry` plugin at the agent failed-step extension point, honoring Retry-After, cancelable delays, and **the retry itself is also a durable event**.

### 9.4 DeepSeek adapter and credentials
- `llm-deepseek`: registers `deepseek-official`; baseURL/key **resolved per request** (settings layered over cordis.yml), key fetched via credential ref (default `DEEPSEEK_API_KEY`), missing reports `MISSING_CREDENTIAL` rather than failing at load; in-flight stream keeps the facts from when it started.
- `credentials-local`: the seam stores a **reference** (env variable name), the provider holds the value; resolution layers (L617): **process environment (wins) > `$DSH_HOME/.credentials.yaml` (managed, writable) > cwd/.env > home/.env** — an explicit env is the current-run intent, the managed store overrides .env so a Models-page write takes effect immediately; cross-process lock + atomic write + patches only its own keys; chokidar hot-publishes external edits; `describe()` (L627) exposes only configured/source/writable, never the value.

### 9.5 Multiple frontends, one loop
- `sdk/server` (`packages/sdk/server/src/server.ts`): subscribes to `session/event`/`agent/status` and forwards as JSON-RPC notifications (L71-87); `session/prompt` → `agent.followup()` (L132-142, fire-and-forget).
- `acp`: one in-flight slot per session, committed-message-granularity push (deliberately trades away token-level latency for clean automation results); `session/request_permission` bridges the approval waterfall.
- Both are transport adapters; scope-filtered dispatch lets each frontend answer only for the agents it owns; interaction rendering belongs to the Web host.

## 10. Enterprise adoption checklist

### Adopt directly (high value)
1. **Event-sourced session log + derived projection** ("model-visible ⟺ logged") — audit / replay / disconnect-recovery / fork solved at once, an enterprise-compliance necessity;
2. **Compaction = a replace operation on the log**: durable lock (start event) + original data never deleted (shadowed) + crash-self-healing detectable (orphan start);
3. **KV-cache awareness end-to-end**: injection always append-only, summarizer replays the warm prefix, policy sections placed after retained history;
4. **Three-stage tool waterfall with immutable arguments**: pre-execute's allow/deny/ask is the natural hook for permissions/approval; post-execute rewrites results without touching arguments;
5. **Fail-closed approval semantics**: closed result set + exceptions/illegal returns normalize to unavailable + `never` decided before any listener (registration order cannot break the guarantee) + asked/decided paired audit + open-turn enclosure;
6. **Credential reference seam**: store the env name not the value, four-layer trust order (env > managed > .env chain), `describe()` never leaks value, errors never echo the secret;
7. **Signal fusion**: a wrapper may only replace `exec.signal`, the registry re-fuses the caller's original signal — middleware cannot detach cancellation;
8. **Monotone subagent depth** persisted in the header, resume cannot reset the recursion budget;
9. **Advisory-only guards**: reminders travel as tagged `additionalContexts` (never rendered as a user turn), never silently veto;
10. **Prepared-call generation binding** prevents hot-update config mix-ups; **fail-loud config validation** (inverted threshold, unknown tool name throw at load);
11. **UI state = pure event fold (projection)**: todos/permissions/plan/approval-policy are all last-wins or structured folds, free resume/fork;
12. **Provider capability negotiation is fail-loud**: unsupported ⇒ typed error, never silent degradation.

### Adapt before use
- The KV-cache invalidation cost of replace-style compaction (from the first replaced token) — known, documented in the README, irreducible;
- SQLite synchronous `DatabaseSync` blocks the JS thread; FTS5 `unicode61` has no substring matching;
- session-query's weak authorization (cwd string equality, no symlink-equivalence) — multi-tenant needs a redesigned trust boundary; the query layer itself has no caller authorization;
- Spill locator depends on a co-located filesystem — remote/container deployment needs a different backend;
- Approval requires an open turn (cannot ask outside a turn, an intentional crash semantic), and ask-user fails directly for delegated subagents — the product layer must absorb these;
- No user-level long-term memory — build your own if needed (session-query is the nearest substitute; or borrow the skill catalog's "list resident + body lazy" pattern);
- agent-instructions has no watcher (touch-driven) — high-churn scenarios need to add their own listener.

### Cost awareness (meta-takeaway)
- This rigor is not free: deep-freeze/snapshot at every boundary, per-execution WeakMap bookkeeping, memoized disposal transactions, very long invariant comments. Teams without multi-tenant durability needs can ship a much simpler loop.
- The fork provider's continuable gap (TODO) reveals the real trap of seeded-prefix children interacting with post-seed prompt sections.
- The most valuable thing to take away is the **invariant-selection method**: write "what must be true" as assertable rules (surface type must carry a marker, approval event pair must be paired, replace shape is whitelisted) and push mechanically-checkable parts into an executed gate — this is worth more than copying any single implementation.
