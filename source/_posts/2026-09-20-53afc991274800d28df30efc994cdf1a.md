# TypeSafe AI 文档高效读取方法（Agent 版）

> 写给自己和其他 agent 复用。目标：读 `docs.typesafe.ai` 时少花 token、少踩坑。
> 实测时间：2026-09。所有 URL 都 curl 验证过，`200` 才写进去，`404` 的坑也标了。

## TL;DR

**一句话：TypeSafe 是 Mintlify 站，agent 友好形态是全系列里最齐的——单页 `.md`、全站 `llms-full.txt`（874KB）、官方 MCP 检索 server、官方 agent skill 都有，纯 curl 就够，连 JS 渲染器都不需要。**

效率排序：

```
llms.txt (找页) + <page>.md (单页)   >   llms-full.txt (全量一次拿)   >   MCP search (按需检索)   >   官方 agent skill (集成场景)   >   爬 HTML
```

- **读单篇** → `<页面URL>.md`（任意页加 `.md` 后缀返回干净 Markdown）
- **找哪一页** → `/llms.txt`（全站 ~40 页索引，每页带 `.md` 直链 + 一句话描述）
- **要通读/喂模型** → `/llms-full.txt`（整个站合并成一个文件，874KB / 20229 行）
- **语义检索** → 官方 MCP server（免鉴权，HTTP transport）
- **帮用户集成 TypeSafe API** → 官方 agent skill（12.8KB，直接放进 Claude Code/Codex）

## 五种形态（都实测）

| 形态 | URL | 状态 | 用途 |
|---|---|---|---|
| **Markdown 单页** | `<页面URL>.md` | ✅ 200, text/markdown | 取单篇正文 |
| **全站索引** | `/llms.txt` | ✅ 200, text/plain | ~40 页目录，每页带 `.md` 链接和描述 |
| **全站全文** | `/llms-full.txt` | ✅ 200, 874,514 B / 20,229 行 | 一次拿全部文档 |
| **MCP server** | `/.well-known/mcp/server-card.json` | ✅ 免鉴权 HTTP | `search_type_safe_ai` + `query_docs_filesystem_type_safe_ai` 两个工具 |
| **官方 agent skill** | `/.well-known/agent-skills/type-safe/skill.md` | ✅ 12,793 B | TypeSafe API 集成速查（何时用、三问型、SDK） |
| A2A card | `/.well-known/agent-card.json` | ✅ 存在 | A2A protocol 0.3，但 capabilities 基本为空，实用价值低 |
| api-catalog | `/.well-known/api-catalog` | ❌ **404** | 响应头 Link 里挂着它，实际不存在（见误区 1） |

## URL 模式（精确，可直接粘）

**1. 单页 Markdown（最常用）**

```bash
# 任意页面加 .md 后缀
curl -s https://docs.typesafe.ai/introduction.md
# → 200, text/markdown; charset=utf-8，干净正文（表格、链接都在）

# 嵌套路径同理
curl -s https://docs.typesafe.ai/primitives/choice.md
curl -s https://docs.typesafe.ai/sdk/python/api/types/questions.md
```

Mintlify 也认 `Accept: text/markdown` header（不带 `.md` 后缀同样返回 Markdown），两种写法等价，`.md` 后缀更直观：

```bash
curl -s -H "Accept: text/markdown" https://docs.typesafe.ai/introduction   # → 200, text/markdown
```

**2. 全站索引（先读它再挑页）**

```bash
curl -s https://docs.typesafe.ai/llms.txt
# → ~40 行，格式：- [标题](https://docs.typesafe.ai/<path>.md): 一句话描述
# 覆盖：concepts / primitives / patterns / demos / sdk (python + javascript) / confidence
```

**3. 全站全文（一次拿完）**

```bash
curl -s https://docs.typesafe.ai/llms-full.txt -o typesafe-docs.md   # 874KB / 20229 行
# 每页带 "Source: <原始URL>" 头，可 grep 定位
grep -n "^Source:" typesafe-docs.md | head    # 快速看有哪些页
```

**4. MCP server（语义检索，免鉴权）**

```bash
curl -s https://docs.typesafe.ai/.well-known/mcp/server-card.json | jq .
# name: "TypeSafe AI Docs MCP"
# url:  https://ts-docs.main-kill-isr.mintlify.me/mcp
# transport: http, authentication: none
# tools: search_type_safe_ai（跨库搜索）、query_docs_filesystem_type_safe_ai（按文件查）
```

支持 MCP 的客户端直接加这个 endpoint，不用每次 curl。

**5. 官方 agent skill（集成场景直接用）**

```bash
curl -s https://docs.typesafe.ai/.well-known/agent-skills/type-safe/skill.md
# 12.8KB：产品定位、何时用/不该用、三种问型速查、SDK 与 API key 说明
# 官方也提供 Claude Code marketplace 安装：claude plugin marketplace add typesafe-ai/skills
```

## Agent 工作流

**读某一篇文档（最常见）：**
1. `curl -s https://docs.typesafe.ai/llms.txt` → 从 ~40 页里挑目标页
2. `curl -s <页面URL>.md` → 拿干净 Markdown，直接进上下文

**要通读或建本地索引：**
1. `curl -s https://docs.typesafe.ai/llms-full.txt -o typesafe-docs.md`（874KB，一次搞定）
2. 按需 grep / 切片喂模型，不用逐页抓

**语义检索（"文档里哪里讲了 X"）：**
- 接 MCP server 用 `search_type_safe_ai`；不想接就 curl llms.txt 看描述 + 单页 `.md`

**帮用户集成 TypeSafe API（写代码、选型）：**
1. 先读官方 skill：`curl -s https://docs.typesafe.ai/.well-known/agent-skills/type-safe/skill.md`
2. 需要细节再按 llms.txt 索引抓对应 `.md` 页

## 工具怎么选

| 工具 | 用在哪 |
|---|---|
| `curl` + `.md` 后缀 | **首选**。任意页 Markdown，零解析、零 JS |
| `curl` + `llms-full.txt` | 全量场景一次拿完（874KB），比逐页抓省调用 |
| MCP client | 语义检索，免鉴权 HTTP endpoint |
| `web_fetch` / unifetch | 兼容这些 URL（本质就是普通 GET），但 curl 更直接 |
| obscura（无头浏览器） | **不需要**。纯静态响应，JS 渲染器是浪费 |

## 常见误区

1. **别信响应头里的 api-catalog**：`Link:` header 挂着 `/.well-known/api-catalog`，实际 curl 返回 404。Mintlify 的模板 header 和实际部署内容不完全一致，以实测为准。
2. **llms-full.txt 不是"摘要"**：它是全站正文合并（874KB），喂模型前按需切片，别整段灌。
3. **`.md` 后缀只对 Mintlify 页有效**：这个模式是 Mintlify 平台通用能力，其他 Mintlify 文档站同样适用；非 Mintlify 站（如 Cloudflare）要改用 `Accept: text/markdown` header。
4. **agent-card.json 别当 API 目录用**：A2A card 存在但 capabilities 基本为空，真正有用的是 llms.txt / MCP / skill 三件套。
