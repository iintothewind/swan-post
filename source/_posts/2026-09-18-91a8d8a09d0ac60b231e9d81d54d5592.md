# vLLM 文档高效读取方法（Agent 版）

> 写给自己和其他 agent 复用。目标：读 `docs.vllm.ai` 时少花 token、少踩坑。
> 实测时间：2026-09；**probe 复测修订 2026-09-21**。
> ⚠️ 修订要点：vLLM 整站在 Cloudflare bot 防护后面，**直连 curl（含 sitemap.xml）拿到的是 "Just a moment..." 挑战页**，不是真内容。取清单/正文都要走渲染（jina/unifetch/obscura）。

## TL;DR

**一句话：vLLM 文档是 MkDocs 生成站 + Cloudflare bot 防护——没有 llms.txt、没有 .md twin、GitHub 也没 .md 源码；而且整站直连 curl 被 CF 挡（挑战页），所以取页面清单和正文都得走渲染（web_fetch / unifetch / obscura）。**

效率排序：

```
web_fetch / unifetch (渲染单页)   >   unifetch/jina 渲染 sitemap.xml (页面清单 ~2688)   >   obscura --stealth (兜底)
```

- **读一篇** → `web_fetch` / `unifetch read <page>`（渲染 + 剥 nav，正文干净）
- **查"有哪些"** → `unifetch read 'https://docs.vllm.ai/sitemap.xml'`（jina 渲染出 ~2688 个页面链接；**不是原始 `<loc>` XML，是 Markdown 链接**）
- **GitHub raw** → 别试，docs 是构建时生成的，仓库里只有 `.meta.yml`，没有 `.md`
- **纯 curl** → 整站被 CF 挡，拿不到真内容

## 为什么不能纯 curl（本次修订的核心）

vLLM 整站在 Cloudflare bot 防护后面。实测：

```bash
curl -s 'https://docs.vllm.ai/sitemap.xml'
# → "Just a moment..." 挑战页（HTML），不是 XML；<loc> 计数 = 0
# sitemap.xml / 任意页面 / llms.txt，直连 curl 全是这个挑战页
```

要过 CF 只能走渲染：

```bash
# jina/unifetch 能过 CF，但把 sitemap 渲染成 Markdown 链接（不是原始 <loc>）
bash ~/.zeroclaw/shared/skills/infra/unifetch/scripts/unifetch.sh read 'https://docs.vllm.ai/sitemap.xml'
# → [unifetch] jina: ok；输出是 [url](url) + 日期 的 Markdown，~2688 个页面
```

## 为什么不用 .md / llms.txt

实测全部拿不到（404 或被 CF 挡）：

- `/llms.txt` → 无
- `/llms-full.txt` → 无
- 任意 `.md` twin（`/index.md`、`/en/latest/features/tool_calling.md`）→ 无
- GitHub raw `docs/api/vllm/README.md` 等 → 404（README 能取是因为它是真文件，docs 页面不是）

**根因**：vLLM 用 MkDocs Material + 每页一个 `.meta.yml`，`.md` 正文是**构建时生成**的，不提交仓库；再叠加 Cloudflare bot 防护。所以没有现成 `.md`，连 sitemap 都要渲染才拿得到。

## URL 模式（精确，可直接粘）

**页面清单（要渲染，别 curl）：**

```bash
# jina/unifetch 渲染 sitemap.xml → Markdown 链接，~2688 页
bash ~/.zeroclaw/shared/skills/infra/unifetch/scripts/unifetch.sh read 'https://docs.vllm.ai/sitemap.xml' \
  | grep -oE 'https://docs\.vllm\.ai/[a-z0-9/_-]+' | sort -u
# → ~2688 个真实页面 URL（/en/latest/api /en/latest/benchmarking ...）
```

**单页（web_fetch / unifetch 渲染取，用服务 URL）：**

```bash
# 首页 / API / Serving
https://docs.vllm.ai/en/latest/
https://docs.vllm.ai/en/latest/api/
https://docs.vllm.ai/en/latest/serving/openai_compatible_server/

# web_fetch 或 unifetch read 都能过 CF + 剥 nav
```

**⚠️ 路径注意**：服务 URL 是 `/en/latest/<section>/`（带版本）。清单里全是这种完整 URL，直接取用即可。

## Agent 工作流

1. **要"有哪些"**：`unifetch read 'https://docs.vllm.ai/sitemap.xml'` → jina 渲染出 ~2688 个页面链接 → 决定读哪页。（**别 curl，会被 CF 挡**）
2. **读单篇**：`web_fetch https://docs.vllm.ai/<url>`（或 `unifetch read`）→ 过 CF + 剥 nav，返回干净正文。
3. **要全量**：~2688 页，没有全量导出。正确做法：清单取 TOC → 逐篇渲染取需要的。

## 工具怎么选

| 工具 | 用在哪 |
|---|---|
| `web_fetch` / `unifetch read` | **首选**。过 CF + 剥 nav，返回干净正文 |
| `unifetch read sitemap.xml` | 拿页面清单（jina 渲染成 Markdown 链接） |
| obscura --stealth | 兜底（CF 更严时） |
| 纯 curl | **别用**——整站被 CF 挡，拿不到真内容 |
| GitHub raw | 别用，docs 是生成的，无 .md |

## 常见误区

1. **别找 llms.txt / .md twin**：vLLM 没有。OpenAI、Claude 有的，vLLM 没有。
2. **别 curl sitemap.xml**：整站在 CF bot 防护后，直连 curl（含 sitemap）拿到的是 "Just a moment..." 挑战页，不是 XML。要 jina/unifetch/obscura 渲染。（本次修订的核心）
3. **jina 渲染的 sitemap 是 Markdown 不是原始 XML**：`<loc>` 标签没了，输出是 `[url](url)` 链接，按这个格式解析。
4. **别抓 GitHub 源码**：docs 构建时生成，仓库只有 `.meta.yml`，`.md` 是 404。
