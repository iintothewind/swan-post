# turbovec (RyanCodrai/turbovec) 评估备忘

> 2026-07-23 评估，供后续 RAG 项目参考

## 基本信息

- 仓库：https://github.com/RyanCodrai/turbovec
- 语言：Rust + Python bindings
- Stars：13.8k (4 个月)
- 协议：MIT
- 核心：Google TurboQuant 算法，data-oblivious quantizer

## 亮点

- 10M docs float32 31GB → 4GB，搜索比 FAISS 快
- Online ingest，无训练阶段，无需 rebuild
- ARM NEON 比 FAISS IndexPQFastScan 快 10-19%
- IdMapIndex 支持稳定 ID、O(1) delete、allowlist 过滤（SIMD kernel 层短路）
- LangChain/LlamaIndex/Haystack/Agno 集成

## 硬伤（PoC 可用，生产等迭代）

| 严重度 | 问题 |
|--------|------|
| 🔴 #121 | Python binding 不释放 GIL，search/add/write/load 全部阻塞其他线程 |
| 🔴 #161 | 并发读写 crash：index 先于 maps 更新，窗口期 search → KeyError |
| 🔴 #159 | dump/persist 非原子：写 index→写 side-car 两步，中间失败直接毁掉已有 store |
| 🔴 #151 | 旋转矩阵不存盘，依赖版本漂移后旧索引静默 recall→0 |
| 🟡 #137 | PyPI wheel 硬编 x86-64-v3，无 AVX2 老 CPU SIGILL |
| 🟡 #119 | n_vectors u32 截断，≥2^32 静默写坏 |
| 🟡 #114 | 文档标 cosine 实际 raw inner product，query 未归一化 |

## 建议

- 适合 PoC，pip install 即可跑，零成本启动
- 单线程只读场景可绕过 #161，但 #121/#159/#151 是硬伤
- 生产上建议等几个大版本迭代，PoC 期间同时保留 FAISS+IVF/SQ8 方案对比
