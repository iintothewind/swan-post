# SkillOpt: Analysis & Application Scenarios

> 原文：Zero（AI agent）与 Ivar 的对话摘要
> 日期：2026-07-26
> 链接：https://github.com/microsoft/SkillOpt

## SkillOpt 是什么

**一句话：把 agent 的 skill 文档（prompt/markdown）当作"可训练参数"来优化。** 不用动模型权重，用另一个 LLM 作为 optimizer，在文本空间里对 skill 做增/删/改操作，通过 validation gate 保证每次修改严格正向收益。

## 核心架构

```
Seed Skill → Rollout（跑任务拿分）→ Reflect（回放获得 insight）
    ↓
Optimizer（LLM 改文本）→ Apply Edit（改 skill 文本）→ Validate（holdout 门控）
```

关键设计：
- **Textual learning-rate budget** — 限制单次修改幅度，防止 optimizer 过度修改
- **Rejected-edit buffer** — 存下失败修改，防止重复踩坑
- **Validation gate** — 只有 strict improvement 才接受，否则回滚
- **Epoch-wise slow/meta update** — 分快/慢步调稳定训练

## 成绩

6 个 benchmark、7 个目标模型、3 种执行环境（直聊 / Codex / Claude Code），全部 52 个测试单元最佳或并列最佳。GPT-5.5 上提升 +23.5 分（直聊）、+24.8（Codex）、+19.1（Claude Code）。

## SkillOpt-Sleep（v0.2.0）

Nightly offline self-evolution 模块。白天干活采集轨迹 → 夜里收割回放 → 生成 skill 补丁 → validation gate → 第二天 skill 自动升级。

## 为什么说它务实

> 真正的价值不是"自动化一切"，而是大幅压缩了从"日常使用数据"到"skill 改进方案"之间的推理成本——这个链路以前全靠人的直觉和经验，现在 optimizer 帮你完成了 80% 的 pattern mining 和 patch generation 工作。

传统 prompt 优化（TextGrad、DSPy 等）需要专门为训练跑大量 rollout，成本高昂。而 SkillOpt 的数据来自用户日常使用：

- **白天干活** → 解决真实问题，tokens 本来就要花，不是浪费
- **夜里收割** → 回放交互副产物（轨迹文本、反馈信号），额外成本只有回放推理
- **产出 diff** → 等你 review，合入版本控制

**隐含前提：你已经在用，它才有用。** 冷启动 agent 没有存量轨迹可收割；但只要日常在用了，边际优化成本就很低。

## 适用场景分类

### 工具类 skill（SkillOpt 增益低）
- 目的：检索、浏览、分析、获取内容
- 质量天花板：确定性为主，数据返回对就行
- 标准变动：基本不动
- 本质是 **capability gating**

### 生成类 skill（SkillOpt 增益高）
- 目的：按规范/约束/模板生成符合要求的内容
- 质量天花板：模糊、主观、持续变化
- 标准变动：甲方改规范、换模板、更新合规要求，经常变
- 本质是 **quality optimization**，手动调 prompt 是无底洞

## 与 ZeroClaw / OpenClaw 的关系

SkillOpt 在 v0.1.0 发布后，社区贡献者为其接了 4 个运行时插件：
- **Claude Code**
- **Codex**
- **Copilot**
- **OpenClaw**（PR #59 @Elzlxx，#72 @Yif-Yang 合入）

OpenClaw 插件包含 `SKILL.md`（文档化全部 22 个 CLI flag、7 个 action、4 个 backend）和 `slash_sleep.py`（schedule/unschedule 子命令）。

这意味着 SkillOpt 可以直接优化 ZeroClaw 的 skill 文件——两者有天然的架构适配：SKILL.md files as optimization targets.

## 核心亮点

1. **定义了一个新问题** — 如何在不动模型权重的前提下，可控可复现地优化 agent 行为
2. **严格的实验范式** — 52 个测试单元、holdout validation gate、ablations，标准的方法论
3. **工程落地意识强** — PyPI 包、4 个运行时插件、WebUI dashboard
4. **"skill 即参数"的隐喻有解释力** — 优化后的 skill 跨模型迁移（GPT-5.5 上优化的可迁移到其他模型）
5. **数据飞轮设计巧妙** — 训练数据标注成本为零，日常使用就是数据生产

## 一个隐忧

依赖"更强的 LLM 做 optimizer"——优化成本取决于 optimizer 模型定价。如果 optimizer 比目标 agent 弱，效果上限受约束。项目默认用 GPT-5.5 或 Claude 4，不便宜。
